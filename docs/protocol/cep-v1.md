# RFC: Chrono Event Protocol (CEP) — Specification v1.0

- **Status**: Final / Normative
- **Date**: October 2026
- **Authors**: Chrono Systems Engineering Team
- **Area**: Agentic Observability & Cryptographic Audit Trails

---

## Abstract

The **Chrono Event Protocol (CEP)** defines an interoperable standard for capturing, serializing, indexing, and cryptographically sealing runtime traces generated by autonomous AI coding agents. It specifies packed binary envelopes, event categories, monotonic ordering requirements, content-addressed checkpointing, and Merkle hash chaining.

---

## 1. Terminology & Conformance

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174].

- **Session**: A discrete execution lifetime of an agent attempting a specified task.
- **Flight Log**: The binary append-only file containing chained CEP records, bearing the file extension `.chrono`.
- **Timeline Index**: A binary lookup table enabling $O(\log n)$ seeking, bearing the file extension `.chronoi`.
- **Checkpoint**: A content-addressed git tree state snapshot anchored to a specific event offset.

---

## 2. Event Kinds

Every CEP event MUST contain an `EventKind` field matching one of the following 16-bit unsigned integer values:

```text
0x0001 - session_start       Session initialization and metadata
0x0002 - session_end         Session finalization
0x000A - prompt              User or automated directive delivered to the agent
0x000B - agent_thought       Model internal reasoning stream / chain-of-thought
0x0014 - tool_call           Invocation of an external tool or command
0x0015 - tool_result         Output/status returned from a tool execution
0x001E - file_diff           Unified diff of workspace filesystem mutations
0x0028 - checkpoint          Content-addressed git tree commit point
0x0032 - terminal_cmd        Interactive shell execution
0x003C - stall_alert         Anomaly detector alert (loop/oscillation)
0x0046 - telemetry_sample    Token-burn and performance sample
0x0050 - intervention        Human or meta-model corrective instruction
```

---

## 3. Cryptographic Chain Invariant

Every record written to a `.chrono` log MUST satisfy:

$$\text{CurrentHash}_i = \text{SHA-256}\Big(\text{Header}_i \parallel \text{PrevHash}_i \parallel \text{Payload}_i\Big)$$

where:
1. $\text{PrevHash}_1$ is equal to the Session Genesis Hash (derived from $\text{SHA-256}(\text{session\_id})$).
2. For all $i > 1$, $\text{PrevHash}_i \equiv \text{CurrentHash}_{i-1}$.
3. $\text{SeqID}_i \equiv \text{SeqID}_{i-1} + 1$.
4. $\text{Timestamp}_i \ge \text{Timestamp}_{i-1}$.

If any byte in any record is modified, the equation fails for that record, or the subsequent record's $\text{PrevHash}$ validation fails.

---

## 4. Checkpoint Invariant

A `checkpoint` record MUST reference a valid git tree hash representing the state of the workspace after applying all preceding `file_diff` records up to `event_offset`.
Seeking to a checkpoint MUST deterministically yield the exact filesystem state that the agent observed at that nanosecond offset.
